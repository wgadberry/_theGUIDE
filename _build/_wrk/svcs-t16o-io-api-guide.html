Unified Transaction Query

GET /api/txs

The unified transaction query endpoint. Replaces both BubbleMap and wallet transaction endpoints with a single call. Supports wallet mode (address provided) and graph mode (address omitted) with a result_mask bitmask controlling which data sections are computed and returned.

Query Parameters
Parameter Type Required Default Description
address string optional — Wallet address. If provided, filters to this wallet. If omitted, returns full token graph.
mint string optional — Token mint address. Required in graph mode.
symbol string optional — Token symbol lookup.
signature string optional — Anchor transaction signature. Centers results around this tx.
limit integer optional 50/10 Max transactions. Default 50 wallet, 10 graph. Max 200/100.
after integer optional — Only tx with block_time > this Unix timestamp.
before integer optional — Only tx with block_time < this Unix timestamp.
type_mask integer optional — Bitmask filter on edge type indicator.
result_mask integer optional 255 Bitmask controlling data sections.
Result Mask Bits
Bit Value Section Description
0 1 Edges Core edge list
1 2 Nodes Address nodes
2 4 Balances Token+SOL balance (requires bit 1)
3 8 Interactions Pool/dex per node (requires bit 1)
4 16 Wallet direction/party/post_balance
5 32 Transactions Flat wallet rows
6 64 Navigation Prev/next
7 128 Related Other tokens
Presets
Mask Name Use Case
113 Wallet Table Wallet history
207 Bubble Map Full graph
255 Full Both views
1 Edges Only Lightweight
0a — Wallet History Wallet table preset
Fetch the most recent 50 transactions for a wallet address using the wallet table preset (result_mask=113). Returns edges, wallet columns, transactions, and navigation.
curl -s "https://svcs.the16oracles.io/api/txs?address=92e59wnU1rQb2uj92dpiSJWQEvqmuNkxjZQGGRh9rLj3&limit=50&result_mask=113" \
  -H "X-API-Key: BMFer"
0b — Wallet by Token Single-asset history
Filter wallet history to a specific token by providing both address and mint. Shows only transactions involving that token for the given wallet.
curl -s "https://svcs.the16oracles.io/api/txs?address=92e59wnU1rQb2uj92dpiSJWQEvqmuNkxjZQGGRh9rLj3&mint=Ha4oiA7TJtoE1jPk8m6r5GPYm1ERmT9oKU5CZAGTpump&limit=50&result_mask=113" \
  -H "X-API-Key: BMFer"
0c — Bubble Map Full graph mode
Omitting address enters graph mode. Provide a mint to get the full token activity graph with nodes, edges, balances, interactions, navigation, and related tokens (result_mask=207).
curl -s "https://svcs.the16oracles.io/api/txs?mint=Ha4oiA7TJtoE1jPk8m6r5GPYm1ERmT9oKU5CZAGTpump&limit=10&result_mask=207" \
  -H "X-API-Key: BMFer"
0d — By Symbol Symbol resolution
Use symbol instead of mint for a human-friendly lookup. The API resolves the symbol to a mint address internally. If multiple tokens share the symbol, the most active is selected.
curl -s "https://svcs.the16oracles.io/api/txs?symbol=PUMP&limit=10&result_mask=207" \
  -H "X-API-Key: BMFer"
0e — Centered on TX Signature anchor
Provide a signature to center the result window around a specific transaction. Combined with mint, this shows the graph around that transaction for the given token.
curl -s "https://svcs.the16oracles.io/api/txs?mint=Ha4oiA7TJtoE1jPk8m6r5GPYm1ERmT9oKU5CZAGTpump&signature=4fXARrfq3prCyfoP354k2dKQaL34eiJt4jQVVbCAD4VDsBqonXuY3XERygrcqaTT5XxdM3grVKJYiu9v1hhB1coC&limit=20&result_mask=207" \
  -H "X-API-Key: BMFer"
0f — Time Range Bounded query
Use after and before with Unix timestamps to restrict results to a specific time window. Combined with wallet + token filtering for precise historical queries.
curl -s "https://svcs.the16oracles.io/api/txs?address=952zmBcstby9cF1UGPBUwRADSNtrMxC2iJ5PYvGmfs2G&mint=Ha4oiA7TJtoE1jPk8m6r5GPYm1ERmT9oKU5CZAGTpump&after=1771900000&before=1773900000&limit=100&result_mask=113" \
  -H "X-API-Key: BMFer"
0g — Edges Only Lightweight
Set result_mask=1 to return only the core edge list — no nodes, balances, or navigation. Ideal for lightweight integrations that only need transfer data.
curl -s "https://svcs.the16oracles.io/api/txs?address=92e59wnU1rQb2uj92dpiSJWQEvqmuNkxjZQGGRh9rLj3&limit=20&result_mask=1" \
  -H "X-API-Key: BMFer"
0h — Full Result All sections
Set result_mask=255 to return every available data section — edges, nodes, balances, interactions, wallet columns, transactions, navigation, and related tokens.
curl -s "https://svcs.the16oracles.io/api/txs?address=92e59wnU1rQb2uj92dpiSJWQEvqmuNkxjZQGGRh9rLj3&mint=Ha4oiA7TJtoE1jPk8m6r5GPYm1ERmT9oKU5CZAGTpump&limit=10&result_mask=255" \
  -H "X-API-Key: BMFer"
0i — Derive Token from TX Signature-only
Provide only a signature — the API derives the token from the transaction and returns the full graph. Useful when investigating a specific on-chain event without knowing which token was involved.
curl -s "https://svcs.the16oracles.io/api/txs?signature=4fXARrfq3prCyfoP354k2dKQaL34eiJt4jQVVbCAD4VDsBqonXuY3XERygrcqaTT5XxdM3grVKJYiu9v1hhB1coC&limit=1&result_mask=207" \
  -H "X-API-Key: BMFer"
0j — Filter by Type Edge type bitmask
Use type_mask to filter edges by their type indicator bitmask. Only edges matching the mask are included in the result.
curl -s "https://svcs.the16oracles.io/api/txs?address=92e59wnU1rQb2uj92dpiSJWQEvqmuNkxjZQGGRh9rLj3&limit=50&type_mask=412316860416&result_mask=113" \
  -H "X-API-Key: BMFer"

Navigation Endpoints

GET /api/tx/{address}/oldest, /latest, /bridge

Endpoints for discovering data coverage boundaries. Use these to find the earliest and latest transactions for an address, or to understand which time ranges have been fetched and where gaps exist.

Oldest Transaction GET /api/tx/{address}/oldest
Returns the oldest transaction signature and block_time for a mint or wallet address. Calls sp_tx_boundary with direction oldest.
curl -s "https://svcs.the16oracles.io/api/tx/6p6xgHyF7AeE6TZkSmFsko444wqoP15icUSqi2jfGiPN/oldest" \
  -H "X-API-Key: BMFer"
Latest Transaction GET /api/tx/{address}/latest
Returns the latest (newest) transaction signature and block_time for a mint or wallet address. Calls sp_tx_boundary with direction latest.
curl -s "https://svcs.the16oracles.io/api/tx/6p6xgHyF7AeE6TZkSmFsko444wqoP15icUSqi2jfGiPN/latest" \
  -H "X-API-Key: BMFer"
Coverage Bridge GET /api/tx/{address}/bridge
Returns the contiguous time coverage for an address by merging overlapping tx_boundary sessions. Identifies gaps between fetched ranges and provides the oldest/newest signatures at bridge edges. Use the optional block_time parameter to select which bridge to inspect.
Query Parameters
block_time Optional Unix timestamp. Selects the bridge containing this time. Defaults to the latest bridge if omitted.
# Latest bridge (default)
curl -s "https://svcs.the16oracles.io/api/tx/6p6xgHyF7AeE6TZkSmFsko444wqoP15icUSqi2jfGiPN/bridge" \
  -H "X-API-Key: BMFer"

# Bridge at a specific time
curl -s "https://svcs.the16oracles.io/api/tx/6p6xgHyF7AeE6TZkSmFsko444wqoP15icUSqi2jfGiPN/bridge?block_time=1773645117" \
  -H "X-API-Key: BMFer"
Response shape: Returns bridge (oldest/newest time + sigs), gaps (adjacent uncovered ranges with fetch_before_bt hints), total_bridges, has_older_bridge, has_newer_bridge, and canyon_before/canyon_after flags indicating whether more history likely exists beyond the outermost bridges.

RAG Search

GET /api/graph/rag/search   POST /api/graph/rag/cluster

Semantic search and clustering over transaction graph edges using OpenAI embeddings and Qdrant vector database. These endpoints proxy to the internal RAG search service.

Semantic Edge Search GET /api/graph/rag/search
Natural-language search over tx_guide edge embeddings. Returns matching edges ranked by similarity score with human-readable sentence summaries.
Query Parameters
q Required. Natural language search query (e.g. "large USDC transfers to Raydium")
limit Max results (1–100, default 20)
address Filter to edges involving this wallet address (as source or destination)
token Token symbol filter
mint Token mint address filter
dex DEX name filter
edge_type Edge type code filter (e.g. swap_in, spl_transfer)
source Source code filter
after Unix timestamp — only edges at or after this time
before Unix timestamp — only edges at or before this time
threshold Minimum similarity score (default 0.25)
# Natural language search
curl -s "https://svcs.the16oracles.io/api/graph/rag/search?q=large+swaps+on+Raydium&limit=10" \
  -H "X-API-Key: BMFer"

# Filtered by wallet and token
curl -s "https://svcs.the16oracles.io/api/graph/rag/search?q=transfers&address=92e59wnU1rQb2uj92dpiSJWQEvqmuNkxjZQGGRh9rLj3&token=USDC&limit=20" \
  -H "X-API-Key: BMFer"

# Time-bounded search
curl -s "https://svcs.the16oracles.io/api/graph/rag/search?q=mint+activity&after=1771900000&before=1773900000&limit=20" \
  -H "X-API-Key: BMFer"
Response shape: { count, results: [{ score, edge_type, block_time_utc, tx_signature, mint_address, from_address, to_address, sentence, token_symbol, dex, amount, pool_label }] }
Holder Clustering POST /api/graph/rag/cluster
Performs PCA → UMAP → HDBSCAN clustering on token holder data. Accepts holder and edge arrays from a BubbleMap response and returns holders annotated with cluster IDs and 2D coordinates for visualization.
curl -s -X POST "https://svcs.the16oracles.io/api/graph/rag/cluster" \
  -H "Content-Type: application/json" \
  -H "X-API-Key: BMFer" \
  -d '{
    "holders": [
      { "address": "92e59...", "percentage": 5.2 },
      { "address": "BAoVY...", "percentage": 3.1 }
    ],
    "edges": [
      { "from": "92e59...", "to": "BAoVY...", "transfer_count": 12, "total_amount": 50000 }
    ]
  }'
Response shape: { holders: [...original fields + cluster_id, x, y], clusters: [{ id, size, members }] }. The x/y coordinates are UMAP-projected positions suitable for 2D scatter plots.

Retrieving BubbleMap Data

GET /api/bmap/get

The BubbleMap endpoint is the primary data retrieval interface. It returns a transaction graph composed of nodes (wallets, pools, mints) and edges (token transfers, swaps, burns) for a given token or transaction. The response is designed to be rendered as an interactive force-directed graph.

ℹ At least one of token_symbol, token_name, mint_address, or signature must be provided to anchor the query.
Query Parameters
Parameter Type Required Default Description
token_symbol string conditional — Token ticker symbol (e.g., TRUMP, SOL, USDC)
token_name string conditional — Full token name (e.g., Wrapped SOL)
mint_address string conditional — On-chain mint address of the token
signature string conditional — A specific transaction signature to visualize
block_time integer optional — Unix timestamp — navigate to the nearest transaction at this time
tx_limit integer optional 10 Number of transactions in the window. Accepted values: 1, 10, 20, 50, 100
1a — By Token Symbol Simplest lookup
When you know the ticker symbol of a token, this is the simplest way to retrieve its activity graph. The API resolves the symbol to a mint address internally and returns the most recent transactions. If multiple tokens share the same symbol, the one with the most transaction activity is selected.
curl -s "https://svcs.the16oracles.io/api/bmap/get?token_symbol=TRUMP&tx_limit=10" \
  -H "X-API-Key: BMFer"
1b — By Mint Address Recommended for integrations
Using the mint address is the most precise way to retrieve data. Unlike symbol-based lookups, there is no ambiguity — every SPL token on Solana has a unique mint address. This is the recommended approach when integrating programmatically.
curl -s "https://svcs.the16oracles.io/api/bmap/get?mint_address=6p6xgHyF7AeE6TZkSmFsko444wqoP15icUSqi2jfGiPN&tx_limit=10" \
  -H "X-API-Key: BMFer"
1c — By Transaction Signature Signature-only mode
Passing a transaction signature retrieves the graph centered on that specific transaction. The API enters signature-only mode, displaying all token activity within the transaction — not just a single token. Useful for investigating a specific on-chain event without knowing which token was involved.
curl -s "https://svcs.the16oracles.io/api/bmap/get?signature=2zMMhcVQEXDtdE6vsFS7S7D5oUodfJHE8vd1gnBouauv&tx_limit=10" \
  -H "X-API-Key: BMFer"
1d — Signature Scoped to a Token Filtered graph
When both a signature and a mint address are provided, the API returns the graph for that specific transaction but filters edges to only show activity involving the specified token. Useful when a transaction involves multiple tokens and you want to focus on one.
curl -s "https://svcs.the16oracles.io/api/bmap/get?signature=2zMMhcVQEXDtdE6vsFS7S7D5oUodfJHE8vd1gnBouauv&mint_address=6p6xgHyF7AeE6TZkSmFsko444wqoP15icUSqi2jfGiPN&tx_limit=10" \
  -H "X-API-Key: BMFer"
1e — Navigate by Block Time Timeline scrubbing
Provide a Unix timestamp and the API will find the nearest transaction to that point. Commonly used for timeline navigation — scrubbing through a token's history to a specific date.
curl -s "https://svcs.the16oracles.io/api/bmap/get?mint_address=6p6xgHyF7AeE6TZkSmFsko444wqoP15icUSqi2jfGiPN&block_time=1773645117&tx_limit=10" \
  -H "X-API-Key: BMFer"
Success Response HTTP 200
{ "result": { "token": { symbol, mint, decimals, token_type }, "txs": { signature, block_time_utc, signer, prev/next navigation }, "nodes": [ { address, label, address_type, balance, ... } ], "edges": [ { source, target, amount, type, token_symbol, dex, pool_label, ... } ], "related_tokens": [ { symbol, mint, tx_count } ] } }
⚠ If no data exists, the API returns HTTP 404 with {"result": {"error": "Token not found"}}. Trigger the producer (Section 3) to source the data, then retry.

Wallet Transaction History

GET /api/bmap/get-wallet-txs

Returns a chronological list of transactions for a specific wallet or entity address. Unlike the BubbleMap endpoint which returns a graph, this returns a flat table of transactions with direction (in/out), amounts, counterparties, and balance information. Supports optional token filtering and can center results around a specific transaction for contextual browsing.

ℹ This endpoint also accepts POST with a JSON body using the same field names.
Query Parameters
ParameterTypeRequiredDefaultDescription
address string required — The wallet, pool, or entity address to query
mint string optional — Filter results to a specific token's activity
signature string optional — Center results around this transaction (half before, half after)
limit integer optional 50 Maximum rows to return (max 200)
2a — All Activity for a WalletMost recent across all tokens
Returns the most recent transactions across all tokens for the given address — transfers, swaps, burns, and mints.
curl -s "https://svcs.the16oracles.io/api/bmap/get-wallet-txs?address=BAoVYrCEjFk7bgP2fRp2ahLcH6ktYUVSgXWHT88jYymy&limit=50" \
  -H "X-API-Key: BMFer"
2b — Activity Filtered by TokenSingle-asset history
Providing a mint address filters results to only show transactions involving that specific token. Useful for tracking a wallet's buy/sell history for a particular asset.
curl -s "https://svcs.the16oracles.io/api/bmap/get-wallet-txs?address=BAoVYrCEjFk7bgP2fRp2ahLcH6ktYUVSgXWHT88jYymy&mint=6p6xgHyF7AeE6TZkSmFsko444wqoP15icUSqi2jfGiPN&limit=50" \
  -H "X-API-Key: BMFer"
2c — Centered Around a TransactionContext window
When a signature is provided, results are split — half are transactions that occurred before the anchor, and half after. The anchor transaction itself is included. Ideal for showing what a wallet did immediately before and after a large swap.
curl -s "https://svcs.the16oracles.io/api/bmap/get-wallet-txs?address=BAoVYrCEjFk7bgP2fRp2ahLcH6ktYUVSgXWHT88jYymy&mint=6p6xgHyF7AeE6TZkSmFsko444wqoP15icUSqi2jfGiPN&signature=2zMMhcVQEXDtdE6vsFS7S7D5oUodfJHE8vd1gnBouauv&limit=50" \
  -H "X-API-Key: BMFer"

Sourcing Transaction Data via the Producer

POST /api/trigger/producer

When the BubbleMap endpoint returns no data, the pipeline has not yet ingested transactions for that token or address. The producer fetches transaction signatures from the Solana blockchain via RPC, then cascades them to the decoder and detailer workers for processing. Once complete (typically 5–30 seconds), BubbleMap data becomes available.

⚠ All producer requests are asynchronous — the endpoint returns immediately with a confirmation, and processing happens in the background via RabbitMQ worker queues.
Standard Request Headers
HeaderValueDescription
Content-Type application/json Required for JSON body
X-API-Key BMFer API key for authentication and billing
X-Priority 8 Queue priority (1–10). User-initiated calls should use 8.
X-Request-Id <UUID> Unique identifier for this request. Auto-generate per call.
X-Correlation-Id <UUID> Groups related requests together. Use the same value across a logical workflow.
3a — Source by Mint AddressMost common
The most common producer call. Given a token's mint address, the producer fetches transaction signatures from the Solana RPC and sends them through the pipeline. address_sig_cnt controls how many qualifying signatures to retrieve — not a page size.
curl -s -X POST "https://svcs.the16oracles.io/api/trigger/producer" \
  -H "Content-Type: application/json" \
  -H "X-API-Key: BMFer" \
  -H "X-Priority: 8" \
  -H "X-Request-Id: $(uuidgen)" \
  -H "X-Correlation-Id: $(uuidgen)" \
  -d '{
    "batch": {
      "filters": {
        "addresses": ["6p6xgHyF7AeE6TZkSmFsko444wqoP15icUSqi2jfGiPN"]
      },
      "address_sig_cnt": 20
    }
  }'
3b — Source by Entity AddressAny Solana address
Works identically to mint-based sourcing, but targets any Solana address — wallets, pools, ATAs, markets, or programs. The producer does not distinguish between address types; downstream workers determine the nature of each transaction.
curl -s -X POST "https://svcs.the16oracles.io/api/trigger/producer" \
  -H "Content-Type: application/json" \
  -H "X-API-Key: BMFer" \
  -H "X-Priority: 8" \
  -H "X-Request-Id: $(uuidgen)" \
  -H "X-Correlation-Id: $(uuidgen)" \
  -d '{
    "batch": {
      "filters": {
        "addresses": ["BAoVYrCEjFk7bgP2fRp2ahLcH6ktYUVSgXWHT88jYymy"]
      },
      "address_sig_cnt": 20
    }
  }'
3c — Source by Signature (Context Mode)Double-click equivalent
When a single signature string is provided, the producer enters context mode. It resolves the address associated with the transaction, then fetches surrounding signatures. sig_adjacent_cnt controls how many signatures to fetch on each side. This is the programmatic equivalent of the BubbleMap viewer's double-click behavior.
curl -s -X POST "https://svcs.the16oracles.io/api/trigger/producer" \
  -H "Content-Type: application/json" \
  -H "X-API-Key: BMFer" \
  -H "X-Priority: 8" \
  -H "X-Request-Id: $(uuidgen)" \
  -H "X-Correlation-Id: $(uuidgen)" \
  -d '{
    "batch": {
      "filters": {
        "signature": "2zMMhcVQEXDtdE6vsFS7S7D5oUodfJHE8vd1gnBouauv",
        "sig_adjacent_cnt": 10
      }
    }
  }'
3d — Source Multiple AddressesParallel processing
Multiple addresses can be submitted in a single request. The producer processes them in parallel using a configurable thread pool. Use the same X-Correlation-Id to track all results as a single logical operation.
curl -s -X POST "https://svcs.the16oracles.io/api/trigger/producer" \

Time-Filtered Sourcing

POST /api/trigger/producer

The producer supports boundary-based filtering using before and until parameters. These accept either a legacy signature string or a structured object with block_time, block_id, or signature. When time boundaries are used, the producer pages through RPC results and only counts transactions that fall within the specified window toward the address_sig_cnt limit.

4a — Most Recent (No Filter)Default behavior
Without any time boundaries, the producer fetches the N most recent transaction signatures for the address.
curl -s -X POST "https://svcs.the16oracles.io/api/trigger/producer" \
  -H "Content-Type: application/json" \
  -H "X-API-Key: BMFer" \
  -H "X-Priority: 8" \
  -H "X-Request-Id: $(uuidgen)" \
  -H "X-Correlation-Id: $(uuidgen)" \
  -d '{
    "batch": {
      "filters": { "addresses": ["6p6xgHyF7AeE6TZkSmFsko444wqoP15icUSqi2jfGiPN"] },
      "address_sig_cnt": 20
    }
  }'
4b — After a Cutoff Date (Until)Lower boundary
The until boundary tells the producer to stop fetching when it reaches transactions older than the specified time. The RPC returns signatures newest-first, so this effectively means "fetch the most recent N signatures, but don't go earlier than this date." Transactions older than the cutoff are not counted toward address_sig_cnt.
curl -s -X POST "https://svcs.the16oracles.io/api/trigger/producer" \
  -H "Content-Type: application/json" \
  -H "X-API-Key: BMFer" \
  -H "X-Priority: 8" \
  -H "X-Request-Id: $(uuidgen)" \
  -H "X-Correlation-Id: $(uuidgen)" \
  -d '{
    "batch": {
      "filters": {
        "addresses": ["6p6xgHyF7AeE6TZkSmFsko444wqoP15icUSqi2jfGiPN"],
        "until": { "block_time": "2025-01-01T00:00:00Z" }
      },
      "address_sig_cnt": 20
    }
  }'
4c — Before a Starting PointUpper boundary
The before boundary tells the producer to begin fetching from a specific point in time rather than from the most recent transaction. Useful for historical analysis — "show me the 50 most recent transactions before June 2026." The producer resolves the time to an RPC-compatible signature cursor internally.

End-to-End Workflow

A typical integration follows this four-step pattern. Use the correlation ID to link the producer call to pipeline monitoring, so you can know exactly when data is ready.

1

Attempt to retrieve BubbleMap data

Try the /api/bmap/get endpoint first. If data exists, you're done. If you receive "error": "Token not found", proceed to Step 2.

curl -s "https://svcs.the16oracles.io/api/bmap/get?mint_address=6p6xgHyF7AeE6TZkSmFsko444wqoP15icUSqi2jfGiPN&tx_limit=10" \
  -H "X-API-Key: BMFer"
2

Trigger the producer to source data

Store a correlation ID to link this request to pipeline monitoring in Step 3.

CORR_ID=$(uuidgen)

curl -s -X POST "https://svcs.the16oracles.io/api/trigger/producer" \
  -H "Content-Type: application/json" \
  -H "X-API-Key: BMFer" \
  -H "X-Priority: 8" \
  -H "X-Request-Id: $(uuidgen)" \
  -H "X-Correlation-Id: $CORR_ID" \
  -d '{
    "batch": {
      "filters": { "addresses": ["6p6xgHyF7AeE6TZkSmFsko444wqoP15icUSqi2jfGiPN"] },
      "address_sig_cnt": 20
    }
  }'
3

Monitor progress (optional)

Poll the pipeline endpoint using the correlation ID to track completion across all workers.

curl -s "https://svcs.the16oracles.io/api/pipeline/$CORR_ID" \
  -H "X-API-Key: BMFer"
4

Retry the BubbleMap call

Allow 5–30 seconds for processing, then retry the original call. Data should now be available.

curl -s "https://svcs.the16oracles.io/api/bmap/get?mint_address=6p6xgHyF7AeE6TZkSmFsko444wqoP15icUSqi2jfGiPN&tx_limit=10" \
  -H "X-API-Key: BMFer"

Reference

Boundary Formats

The before and until fields accept multiple formats:

Supported Boundary Formats
// ISO 8601 datetime (resolved to nearest RPC signature via binary search)
"before": { "block_time": "2026-06-15T00:00:00Z" }

// Slot number
"before": { "block_id": 350000000 }

// Specific transaction signature
"before": { "signature": "2zMMhcVQEXDtdE6vsFS7S7D5oUodfJHE8vd1gnBouauv" }

// Legacy format: plain signature string
"before": "2zMMhcVQEXDtdE6vsFS7S7D5oUodfJHE8vd1gnBouauv"
Priority Levels
10 Critical real-time operations
8 User-initiated requests (recommended)
5 Normal background processing
1 Bulk batch operations
HTTP Status Codes
200 Success — data returned
202 Accepted — async processing started
400 Bad request — missing or invalid parameters
401 Unauthorized — missing or invalid API key
403 Forbidden — feature not enabled for this key
404 Not found — no data exists for the query
429 Rate limit exceeded
500 Internal server error

Rate Limiting

Rate limits are enforced per API key using a sliding 60-second window. When the limit is exceeded, the API returns HTTP 429 with a Retry-After header indicating the number of seconds to wait before retrying.
